# Reviewer Checklist

Use this checklist whenever you are asked to review a pull request.

- [ ] Read the PR description and understand the intent of the change.
- [ ] Walk the diff top to bottom before leaving any comments.
- [ ] Check that the change is covered by tests (or explain why it isn't).
- [ ] Look for error handling and edge cases in new code paths.
- [ ] Flag anything that looks like a secret, credential, or sensitive data.
- [ ] Comment on the specific line in question, not the whole file.
- [ ] End the review with a clear verdict: approve, request changes, or comment.
